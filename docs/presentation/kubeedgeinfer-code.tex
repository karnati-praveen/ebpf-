  \frametitle{Measuring network delay inside the kernel}

    \kepath{internal/ebpf/bpf/tcpmon.c}
    \lstset{style=kepanel,language=C}
    \begin{lstlisting}
struct flow_val {
    __u64 bytes;         // cumulative payload bytes
    __u64 srtt_us;       // most recent smoothed RTT
    __u64 srtt_samples;  // cumulative tcp_probe hits
};

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __type(key,   struct flow_key);
    __type(value, struct flow_val);
} flows SEC(".maps");

SEC("tp_btf/tcp_probe")
int BPF_PROG(tcp_probe_hook, struct sock *sk,
                             struct sk_buff *skb)
{
    struct tcp_sock *tp = (struct tcp_sock *)sk;
    __u32 srtt = BPF_CORE_READ(tp, srtt_us) >> 3;
    val->srtt_us = srtt;
    __sync_fetch_and_add(&val->srtt_samples, 1);
    return 0;
}

SEC("fentry/tcp_sendmsg")
int BPF_PROG(tcp_sendmsg_hook, struct sock *sk,
             struct msghdr *msg, size_t size)
    \end{lstlisting}
  \end{column}
  \begin{column}{0.40\textwidth}
    \kenote[keamber]{Why we use the kernel's own number}{%
      Linux already tracks the round-trip time of every connection, because it
      needs it to manage traffic. Reading that number costs nothing, and it
      cannot be wrong the way a timer inside the program can.}\par\vspace{0.5em}
    \kenote{Build once, run anywhere}{%
      The program adjusts itself to the running kernel when it is loaded. So one
      compiled file works on any modern Linux kernel, with no rebuilding.}\par\vspace{0.5em}
    \kenote{We only watch what we need}{%
      We only look at connections between our own machines. The controller then
      matches each connection to the machine it came from.}
  \end{column}
  \end{columns}
  \kefoot{Demo: show the live readings with \texttt{kubectl logs}}
\end{frame}

% =============================================================== 4. DECIDE
\begin{frame}[fragile,shrink=30]
  \framesubtitle{2. DECIDE}
  \frametitle{The solver that picks the cut}
  \begin{columns}[T]
  \begin{column}{0.56\textwidth}
    \kepath{internal/partition/partition.go}
    \lstset{style=kepanel,language=Go}
    \begin{lstlisting}
// stageCost: receive + compute for one stage.
// An empty stage is skipped by the router entirely,
// so it costs nothing - not even its hop.
func stageCost(in Input, worker, layers int) float64 {
    if layers == 0 {
        return 0
    }
    cost := float64(layers) * in.PerLayerMs /
            math.Max(in.Workers[worker].Speed, 0.01)
    if worker > 0 {
        cost += in.LinkMs[worker-1]
    }
    return cost
}

// Optimal solves the linear partition in O(N^2 * K).
for w := 1; w <= k; w++ {
  for j := 0; j <= n; j++ {
    for split := 0; split <= j; split++ {
      cost := math.Max(f[split][w-1],
              stageCost(in, w-1, j-split))
      if cost < f[j][w] {
        f[j][w] = cost
        choice[j][w] = split
      }
    }
  }
}
    \end{lstlisting}
  \end{column}
  \begin{column}{0.40\textwidth}
    \kenote{\texttt{f[j][w]}}{%
      The best we can do for the first $j$ layers on the first $w$ machines.
      The final answer is \texttt{f[N][K]}, and \texttt{choice} tells us where
      the cuts go.}\par\vspace{0.5em}
    \kenote{Heat is just a slower speed}{%
      Each machine has one \texttt{Speed} number. When it gets hot, that number
      drops. So the solver has no special code for heat anywhere --- it just
      sees a slower machine.}\par\vspace{0.5em}
    \kenote[keamber]{A machine can get zero layers}{%
      That one line is what lets the solver skip a machine with a bad network.
      Nobody wrote a rule for skipping --- it falls out of the maths.}
  \end{column}
  \end{columns}
  \kefoot{Demo: \texttt{go test ./internal/partition/...} --- it checks the
          solver against brute force on 200 random cases.}
\end{frame}

\begin{frame}[fragile,shrink=30]
  \framesubtitle{3--4. ACT and HEAL}
  \frametitle{From a decision to a running system}
  \begin{columns}[T]
  \begin{column}{0.56\textwidth}
    \kepath{internal/partition/partition.go -- Decider}
    \lstset{style=kepanel,language=Go}
    \begin{lstlisting}
func (d *Decider) Decide(now time.Time, in Input,
                         force bool) (*Result, bool, error) {
    opt, err := Optimal(in)
    if d.current == nil || force ||
       workersChanged(d.current, in.Workers) {
        d.current, d.lastChange = opt, now
        return opt, true, nil          // healing path
    }
    currentCost := Evaluate(in, d.current.Splits())
    improved := opt.BottleneckMs <
                currentCost*(1-d.ImprovementFrac)
    if improved && now.Sub(d.lastChange) >= d.Cooldown {
        d.current, d.lastChange = opt, now
        return opt, true, nil          // hysteresis passed
    }
    \end{lstlisting}
    \vspace{0.5em}
    \kepath{demo -- make a machine hot, then cool it again}
    \lstset{style=kepanel,language=sh}
    \begin{lstlisting}
W2=$(docker inspect -f '{{range .NetworkSettings.Networks}}\
     {{.IPAddress}}{{end}}' kubeedgeinfer-worker2)
curl -X POST http://$W2:9101/gpu/override -d '{"temp_c": 92}'
curl -X POST http://$W2:9101/gpu/override -d '{"clear": true}'
    \end{lstlisting}
  \end{column}
  \begin{column}{0.40\textwidth}
    \kenote{Three ways out, one function}{%
      If a machine appears or dies, re-cut at once. If a new cut is clearly
      better and enough time has passed, apply it. Otherwise keep the current
      cut and just update its cost.}\par\vspace{0.5em}
    \kenote{We compare fairly}{%
      Before comparing, we re-score the cut we are already using with today's
      readings. Otherwise we would be comparing against an old number.}\par\vspace{0.5em}
    \kenote[keamber]{Changing the cut with no restart}{%
      The controller saves the new layer ranges in Kubernetes and sends them to
      the machines with a new version number. Machines refuse messages from an
      old version. The router then fetches the new plan and replays the request
      from the start. Machines keep no state, so replaying is always safe.}
  \end{column}
  \end{columns}
  \kefoot{Layers move off the hot machine in about 35 seconds, and come back
          once it cools down.}
\end{frame}

% =============================================================== 6. Runbook
\begin{frame}[fragile,shrink=30]
  \framesubtitle{Demo}
  \frametitle{Runbook}
  \footnotesize
  \begin{enumerate}\itemsep0.55em
    \item \textbf{One command starts everything} ---
      \texttt{\small ./run-demo.sh}\newline
      {\scriptsize\color{kebody}Builds everything, starts the cluster, and opens
       a live dashboard on \texttt{localhost:8000} showing the machines, how busy
       each one is, the network delays, and a log of every re-cut.}
    \item \textbf{Watch the plan change} ---
      \texttt{\small kubectl -n kubeedgeinfer get ipl demo -w}\newline
      {\scriptsize\color{kebody}The layer ranges and the version number update as
       the controller re-plans.}
    \item \textbf{Send it some work} ---
      \texttt{\small kubectl -n kubeedgeinfer port-forward svc/router 8080:8080}\newline
      \texttt{\small curl -X POST localhost:8080/generate -d
       '\{"prompt\_len":16,"max\_new\_tokens":8\}'}\newline
      {\scriptsize\color{kebody}The router sends each request through the
       machines in order.}
    \item \textbf{Break something on purpose} ---
      \texttt{\small curl -X POST http://\$W2:9101/gpu/override -d
       '\{"temp\_c": 92\}'}\newline
      {\scriptsize\color{kebody}Or press the buttons on the dashboard. Layers
       move off the hot machine, then come back once it cools.}
    \item \textbf{Reproduce the numbers} ---
      \texttt{\small go run ./bench/dpsim}\newline
      \texttt{\small python3 bench/run.py -{}-all \&\& python3 bench/plot.py}\newline
      {\scriptsize\color{kebody}\texttt{dpsim} reproduces the numbers on slide
       11 of the main deck with no cluster at all. \texttt{bench/run.py} needs
       the running cluster and measures words per second and idle time.}
  \end{enumerate}
  \kefoot{You need: a modern Linux kernel, Docker, kind, kubectl and
          Python 3.11 or newer.}
\end{frame}
